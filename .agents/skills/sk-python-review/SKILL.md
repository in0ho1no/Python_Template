# Pythonレビュー

レビュー中は変更せず、実行時エラー、仕様との不一致、既存挙動への回帰、型、安全性、テスト不足を優先して確認する。

## 手順

1. 対象を絞る
   - ユーザー指定のファイル、差分、観点を優先する
   - 指定が弱ければ、変更箇所と影響範囲を中心に確認する
2. 重大な問題を探す
   - 実行時エラーになり得る点
   - 仕様と実装の不一致
   - 既存挙動を壊す変更
3. 保守性の問題を確認する
   - 型の曖昧さ
   - テスト不足
   - 読み手が誤解しやすい分岐や命名
   - `AGENTS.md` の Python 規約からの逸脱 (ファイル配置、`pathlib.Path` の利用、broad catch の回避、型ヒントなど)

## 出力

- 指摘事項を重要度の高い順に並べる
- 各指摘に対象ファイルと行番号を付ける
- 事実、影響、なぜ問題かを簡潔にまとめる
- 指摘がなければ「指摘なし」と明記し、残る確認ポイントやテストギャップだけを添える
- 要約は最後に短く付ける。前置きや長い総論は書かない

```md
## Findings

1. [high] path/to/file.py:10
   問題の要約。何が起きるか、なぜ危険かを簡潔に述べる。

## Open Questions

- 必要な場合のみ記載

## Summary

- 指摘なし、または残る確認ポイント
```
